# 微博VIP增量爬取功能指南

## 📖 功能介绍

微博VIP模式现已支持增量爬取功能！可以大幅提升VIP内容爬取效率，避免重复爬取已有内容。

### 核心优势

- ✅ **效率提升**: 10-500倍效率提升
- ✅ **智能早停**: 遇到已存在内容自动停止
- ✅ **精准定位**: 记录每个VIP创作者的最新内容位置
- ✅ **向下兼容**: 不启用时完全不影响现有功能

---

## 🚀 快速开始

### 1. 启用增量爬取

编辑 `config/base_config.py`：

```python
# ==================== 增量爬取配置 ====================
# 启用增量爬取
ENABLE_INCREMENTAL_CRAWL = True

# 创作者模式 - 早停阈值（连续N条已存在就停止）
CREATOR_EARLY_STOP_THRESHOLD = 3  # 推荐 3-5
```

### 2. 开始爬取

运行微博VIP爬取：

```bash
python main.py --platform wb --type creator_vip --vip_creator_id YOUR_VUID
```

或者配置多个VIP创作者：

```python
# config/weibo_config.py
WEIBO_VIP_CREATOR_ID_LIST = [
    "vuid_001",
    "vuid_002",
    "vuid_003",
]
```

然后运行：

```bash
python main.py --platform wb --type creator_vip
```

## 💡 工作原理

### 增量爬取流程

```
┌─────────────────────────────────────────────────────┐
│ 1. 查询历史数据                                      │
│    last_content = get_last_crawled_note(vuid)       │
│    → 从 DB/JSON/CSV 查询最新VIP内容                 │
└─────────────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────┐
│ 2. 获取第一页内容（20条）                           │
│    first_page = fetch_page(1)                       │
│    → [新1, 新2, 旧1, 旧2, 旧3, ...]                │
└─────────────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────┐
│ 3. 逐个检查 + 早停（第一页）                        │
│    检查 新1 → 不存在 → 添加                         │
│    检查 新2 → 不存在 → 添加                         │
│    检查 旧1 → 已存在 → stop_count = 1              │
│    检查 旧2 → 已存在 → stop_count = 2              │
│    检查 旧3 → 已存在 → stop_count = 3              │
│    stop_count >= 3 → 🛑 停止！                     │
└─────────────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────┐
│ 4. 如果第一页未触发早停，继续爬取后续页             │
│    for page in range(2, total_pages):              │
│      检查每条内容                                    │
│      如果连续N条已存在 → 提前终止                   │
└─────────────────────────────────────────────────────┘
                      ↓
┌─────────────────────────────────────────────────────┐
│ 5. 保存数据 + 更新元数据                            │
│    save_to_db(new_contents)                         │
│    update_metadata(vuid, latest_content)            │
└─────────────────────────────────────────────────────┘
```

### 效率对比

#### 不使用增量（传统方式）
```
第1页: 获取20条 → 全部保存
第2页: 获取20条 → 全部保存
第3页: 获取20条 → 全部保存
...
第50页: 获取20条 → 全部保存
总计: 1000条内容 ❌ 慢
```

#### 使用增量（早停策略）
```
查询历史: 找到最新内容 mid_999
第1页: 获取20条
  - 新1, 新2 → 保存
  - 旧1, 旧2, 旧3 → 已存在
  - stop_count = 3 → 🛑 停止！
总计: 2条新内容 ✓ 快！
效率提升: 1000条 → 2条 = 500倍！
```

## 🔧 配置参数

### `ENABLE_INCREMENTAL_CRAWL`

**类型**: bool  
**默认值**: False  
**说明**: 是否启用增量爬取功能

```python
ENABLE_INCREMENTAL_CRAWL = True  # 启用
ENABLE_INCREMENTAL_CRAWL = False  # 禁用（全量爬取）
```

### `CREATOR_EARLY_STOP_THRESHOLD`

**类型**: int  
**默认值**: 3  
**说明**: 连续遇到N条已存在的内容就停止爬取

**推荐值**:
- `3`: 适合更新频繁的VIP创作者（推荐）
- `5`: 更保守，适合更新不规律的创作者
- `1`: 激进模式，但可能因为内容删除导致遗漏

**示例场景**:

```python
# 场景1: VIP创作者正常更新
内容列表: [新1, 新2, 旧1, 旧2, 旧3, ...]
阈值=3时: 爬取新1、新2，遇到旧1/旧2/旧3后停止 ✅

# 场景2: VIP创作者删除了一条旧内容
内容列表: [新1, 旧1, [已删除], 旧2, 旧3, ...]
阈值=1时: 爬取新1，遇到旧1就停止，遗漏检测 ❌
阈值=3时: 爬取新1，遇到旧1/旧2/旧3后停止 ✅
```

## 🐛 故障排查

### Q1: 为什么增量不生效？

**检查清单**:
1. ✅ 确认 `ENABLE_INCREMENTAL_CRAWL = True`
2. ✅ 确认数据库中有历史VIP内容
3. ✅ 查看日志是否有 `[VIP增量]` 相关信息
4. ✅ 确认存储模式正确（db/sqlite/json/csv）

**测试命令**:
```bash
python test_vip_incremental.py
```

### Q2: 为什么有些新内容被跳过了？

**原因**: `CREATOR_EARLY_STOP_THRESHOLD` 设置过小

**解决方案**: 设置为 3-5
```python
CREATOR_EARLY_STOP_THRESHOLD = 3  # 推荐值
```

### Q3: 可以中途启用增量吗？

**答案**: 可以！

首次启用时，系统会自动查询数据库中已有的最新VIP内容作为基准，后续只爬取新内容。

### Q4: 如何重新全量爬取某个VIP创作者？

**方法1**: 临时禁用增量
```python
# 在 main.py 开头添加
import config
config.ENABLE_INCREMENTAL_CRAWL = False
```

**方法2**: 删除元数据（数据库模式）
```sql
DELETE FROM incremental_metadata 
WHERE platform='weibo_vip' 
  AND crawler_type='creator' 
  AND target_key='YOUR_VUID';
```
